# CopyBox v3.0 架构蓝图与更新规划说明书 (v3.0 Architecture & Roadmap Specification)

> **文档状态**：已对齐确认（为 v3.0 研发做铺垫，当前线上稳定版本保持为 v2.2.2）  
> **制定日期**：2026-11-09  
> **核心愿景**：从“极速离线的剪贴板与贴边效率抽屉”进化为 **“Windows 桌面级个人离线生产力、视觉检索与局域网跨端中枢”**。

---

## 1. 核心设计铁律与底线约束 (Core Principles)

在向 v3.0 跨越演进的过程中，始终严格恪守 CopyBox 的立身之本：

| 维度 | 核心约束指标 | 技术保障策略 |
| :--- | :--- | :--- |
| **100% 离线隐私安全** | 零公网请求、零云端中转服务器、零遥测上报 | OCR 采用系统内置离线引擎；跨设备同步严格限制在本地物理局域网（LAN）内点对点加密通信 |
| **极致轻量化内存** | 常驻物理内存维持在 **50MB ~ 75MB** | 延续 v2.2.2 的 UI 虚拟化回收、400px 约束解码、`EmptyWorkingSet` 主动收缩与后台按需启停机制 |
| **单文件免安装便携** | 单一 `CopyBox.exe` 开箱即用，数据默认随根目录走 | 原生库与前端微页面资源全部内嵌至单文件程序集，零外部零散文件依赖 |
| **双形态 100% 互通** | v2.0 贴边抽屉与 v1.0 居中浮窗完整保留且配置同源 | 所有新增的标签分组、OCR 检索、局域网快传在双形态下共享同一套底层服务与 SQLite 数据源 |

## 2. v3.0 四大核心更新模块详解 (The 4 Pillars of v3.0)

### 2.1 【模块一】🖼️ 原生离线 OCR 文字提取与以文搜图 (Native Offline OCR & Visual Search)

#### 痛点与场景
日常办公或开发时，用户经常复制截图（如报错弹窗、PDF 扫描件、网页防复制段落、聊天图片、发票单据）。过去想要提取图片中的文字必须打开第三方软件或上传微信，效率低下且存在隐私泄露隐患。

#### 技术实现方案
1. **零体积膨胀的原生引擎**：
   - 直接调用 Windows 10/11 内置的原生 WinRT API `Windows.Media.Ocr.OcrEngine`（通过 `OcrEngine.TryCreateFromUserProfileLanguages()` 自动匹配系统已安装的中文/英文语言包）；
   - **无需打包任何第三方 OCR 模型（如 PaddleOCR/Tesseract）**，主程序体积实现 **0 MB 增长**，且 100% 本地离线运算。
2. **后台低优先级异步流水线**：
   - 当 `ClipboardMonitorService` 捕获到图片并保存至本地 `images/` 目录后，立即向界面投递图片卡片（确保毫秒级上屏，零卡顿）；
   - 同时在后台 `Task.Run` 低优先级线程中对图片执行离线 OCR 识别，提取出的纯文本异步回写至 SQLite 数据库该条记录的 `OcrText` 字段。
3. **交互体验与功能闭环**：
   - **一键提取图片文字**：当图片识别出包含文字时，图片卡片右上角自动浮现 **`[ 📝 提取文字 ]`** 微型徽标按钮；点击即可弹出文字预览/编辑层，或直接将图片内的文字一键复制/粘贴到目标窗口；
   - **搜文字直接出截图（以文搜图）**：在顶部搜索框输入关键词时，SQL 查询同时检索 `Content`（文本内容）与 `OcrText`（图片内文字）。命中的截图卡片将显示醒目的 **`🔍 命中图中文字`** 提示标签。

### 2.2 【模块二】📱 局域网离线加密互传：PC 点对点同步 + 手机扫码免安装网页快传 (Local LAN Sync & Mobile Web Drop)

#### 痛点与场景
用户在电脑与手机（Android / iOS）或两台办公电脑之间互传一段文字、验证码、链接或截图时，往往被迫登录微信文件传输助手或第三方云剪贴板，不仅步骤繁琐，且敏感数据经过第三方公网服务器留存。

#### 交互形态设计（已确认采用：PC 端自动点对点 + 手机端免安装扫码网页双向快传）

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       CopyBox v3.0 局域网跨端架构                        │
├───────────────────────────────────┬─────────────────────────────────────┤
│   💻 PC ⇄ 💻 PC (CopyBox 客户端)   │   📱 手机 ⇄ 💻 PC (免安装扫码快传)    │
│  • UDP 局域网广播自动发现设备       │  • 内置轻量级按需启动 HTTP/Web 服务    │
│  • 首次 6 位 PIN 码配对信任         │  • 侧边栏点击 [📱 手机快传] 弹出二维码 │
│  • TLS / AES-256-GCM 端到端加密    │  • 手机相机/浏览器扫码即开极简交互页   │
│  • 复制内容毫秒级双向静默流转       │  • 手机发文字/图 ➔ 电脑剪贴板秒出卡片  │
│                                   │  • 电脑剪贴板列表 ➔ 手机一键复制/存图  │
└───────────────────────────────────┴─────────────────────────────────────┘
```

#### 技术实现方案
1. **按需启停的内置微服务端（零闲置内存开销）**：
   - 基于 .NET 原生 `HttpListener` 或轻量级 Socket 构建，前端 HTML/CSS/JS 单页应用（约 15KB）直接作为内嵌资源编译进 `CopyBox.exe`；
   - 仅当用户开启“局域网互传”或打开“手机扫码面板”时启动监听，关闭后立即释放端口与内存。
2. **手机端零门槛双向交互**：
   - **局域网安全鉴权**：二维码 URL 内含随机生成的一次性会话 Token（例如 `http://192.168.1.105:52888/?t=a8f92c`），防止同局域网未授权访问；
   - **手机发往电脑**：手机网页端提供大号输入框与“发送相册图片/拍照”按钮，点击发送后，电脑端 CopyBox 瞬间捕获并存入剪贴板中心（标注来源为 `📱 手机快传`）；
   - **电脑发往手机**：手机网页端实时展示电脑端最近 20 条剪贴板记录（对于敏感遮罩内容默认打码，需在手机端点击解锁），手机点击即可一键复制文本或长按保存高清原图。
3. **多台 Windows 电脑间自动同步**：
   - 支持局域网内两台运行 CopyBox 的电脑通过设备发现配对，配对后支持“复制即自动同步到对方剪贴板历史”或“右键卡片 ➔ 发送至另一台电脑”。

### 2.3 【模块三】📂 升级版动态分类标签药丸栏与智能模板变量 (Dynamic Tag Pills & Smart Snippet Variables)

#### 痛点与场景
随着长期使用，用户置顶（Pin）的重要内容越来越多（如常用邮箱、银行卡号、Git 命令、SQL 查询模板、客服回复话术），单一的“置顶”分类显得杂乱，且缺少动态填充日期/剪贴板变量的能力。

#### 交互形态设计（已确认采用：原位升级现有分类药丸栏，保持顶栏双模极简）
1. **动态可扩展分类药丸栏**：
   - 保持现有的 `[ 📋 剪贴板中心 | ⚡ 快捷看板 ]` 顶栏双模结构不变，绝不增加冗余层级；
   - 将搜索框下方的分类药丸栏改造为支持鼠标滚轮横向滑动的 **动态标签栏**：
     `[ 全部 ] [ 文本 ] [ 图片 ] [ 代码 ] [ ⭐ 置顶 ] [ 💼 工作 ] [ 💻 脚本 ] [ ➕ ]`
   - 点击末尾的 **`[ ➕ ]`** 按钮，可快速输入名称（支持选配 Emoji 前缀）创建自定义标签分组；右键点击自定义药丸可重命名、调整顺序或删除。
2. **卡片标签归档与免清理保护**：
   - 卡片右键菜单与 `···` 菜单新增 **`🏷️ 归入标签 ➔ [选择分组]`**；
   - 凡是归入自定义标签分组的卡片，在卡片底部展示精致的标签微章，且**自动享受与“置顶”同等的生命周期保护**（不会因超出历史记录条数上限而被自动淘汰）。
3. **轻量级动态模板占位符（Macro Variables）**：
   - 支持在卡片内容中使用双花括号动态变量，双击或快捷键粘贴上屏时实时计算替换：
     - `{{date}}` ➔ 自动替换为当前日期（如 `2026-11-09`）
     - `{{time}}` ➔ 自动替换为当前时间（如 `22:55:00`）
     - `{{datetime}}` ➔ 自动替换为完整时间戳
     - `{{clipboard}}` ➔ 自动嵌套插入当前系统剪贴板中的最新文本

### 2.4 【模块四】🎨 Windows 11 原生材质进化与微触感交互 (Native Mica/Acrylic & Micro-Feedback)

#### 技术实现方案
1. **底层 DWM 原生云母（Mica）与亚克力（Acrylic）直出**：
   - 针对 Windows 11 (Build 22621+) 系统，通过 `dwmapi.dll!DwmSetWindowAttribute` (`DWMWA_SYSTEMBACKDROP_TYPE = 38`) 提供原生系统级材质开关（`Mica` / `Tabbed Mica` / `Transient Acrylic`）；
   - 由操作系统 DWM 桌面窗口管理器在 GPU 合成层直接渲染桌面壁纸漫反射采样，**CPU 占用为 0**，同时完美向下兼容 Windows 10 及现有的 6 大预设主题、自定义图片壁纸与 120FPS 真实背景透明度滑块。
2. **极客级微触感音效（可选开关）**：
   - 在内存中通过极简正弦波/包络合成或内嵌极小音频流（< 30KB），提供三处微秒级精致听觉反馈：
     - **复制捕获音**：极轻柔的纸张摩擦或清脆微滴声；
     - **贴边唤出音**：丝滑的空气滑动微音；
     - **秒贴上屏音**：轻快的机械轴体确认音；
   - 在偏好设置中提供 **`🔊 开启交互微音效`** 独立开关（默认可随时一键静音，且在全屏游戏免打扰模式下自动静默）。

## 3. 数据库平滑无感升级设计 (Database Schema Evolution)

为确保 v2.2.2 及更早版本的用户升级至 v3.0 时 **“直接覆盖 `CopyBox.exe` 即可 100% 保留原有历史与配置”**，`DatabaseService` 将在启动时执行幂等表结构演进：

```sql
-- 1. 为 ClipboardItems 表无损扩展 OCR 文本与自定义标签字段
ALTER TABLE ClipboardItems ADD COLUMN OcrText TEXT DEFAULT '';
ALTER TABLE ClipboardItems ADD COLUMN CustomTag TEXT DEFAULT '';

-- 2. 创建自定义标签分组元数据表
CREATE TABLE IF NOT EXISTS CustomTags (
    Id INTEGER PRIMARY KEY AUTOINCREMENT,
    TagName TEXT NOT NULL UNIQUE,
    TagIcon TEXT DEFAULT '🏷️',
    SortOrder INTEGER DEFAULT 0,
    CreatedAt TEXT NOT NULL
);

-- 3. 为 CustomTag 与 OcrText 建立检索索引
CREATE INDEX IF NOT EXISTS idx_clipboard_custom_tag ON ClipboardItems(CustomTag);
```

## 4. 分阶段开发实施路线图 (Phased Implementation Plan)

当正式启动 v3.0 研发时，建议按以下四个里程碑稳步推进并逐阶段验证：

- **Milestone 1：数据层演进 + 动态分类标签药丸栏与模板变量（模块三）**
  - 完成 SQLite 表结构自动升级与 `CustomTags` 管理接口；
  - 升级主界面与侧边栏的分类药丸栏，支持 `+ 新建标签`、卡片右键归类与 `{{date}}` 等模板变量解析。
- **Milestone 2：Windows 原生离线 OCR 引擎与以文搜图（模块一）**
  - 集成 `Windows.Media.Ocr` 后台异步识别服务；
  - 实现图片卡片 `[ 📝 提取文字 ]` 交互按钮与搜索框 `OcrText` 联合高亮检索。
- **Milestone 3：局域网离线互传与手机扫码免安装快传（模块二）**
  - 构建内嵌式局域网加密微服务端与二维码生成面板；
  - 完成手机端响应式快传 Web 页（双向文字/图片秒传）及 PC 间局域网自动发现同步。
- **Milestone 4：Win11 原生材质、微触感音效与 v3.0 正式发布（模块四）**
  - 接入 DWM 原生云母/亚克力特性与可选微音效；
  - 进行全链路内存压力测试（确保后台休眠依然稳定在 ~55MB），同步更新中英双语 `README.md`，并按 60FPS + 1.0 固定男音标准制作 B 站 v3.0 宣传视频。
